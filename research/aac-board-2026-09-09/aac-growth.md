## Part 1 — How incumbent products handle growth

### 1. Tobii Dynavox TD Snap "Core First"

- **Grid-size progression range.** Core First offers grid sizes from 1x1 up through 8x10 (documented sequence includes 1x1, 1x2, 2x2, 2x3, 3x3, 3x4, 4x4, 5x5, 6x6, 7x7, 7x9, 8x10), explicitly marketed as "a selection of grid sizes that grow as communication skills advance." **VERIFIED** — https://us.tobiidynavox.com/pages/td-snap-core-first ; https://us.tobiidynavox.com/blogs/support-articles/where-did-my-custom-topics-go-when-i-change-the-page-set-grid-size-core-first-page-set
- **What happens to positions on grid change: "Block Flow" + "saved states."** TD Snap's support article documents two mechanisms: (a) Block Flow (default): "TD Snap will attempt to preserve the position of the buttons in the visible columns. Buttons in columns that are no longer visible will be moved to the first available empty rows." (b) Saved states: once you manually reposition any button, TD Snap creates a saved state for that grid size, and there are *two* saved states per grid size (navigation buttons on vs. off). **VERIFIED** — https://www.tobiidynavox.com/blogs/support-articles/understanding-pages-and-button-grids-in-td-snap
- **Motor-plan preservation is partial and breaks on customization.** Because every pre-made Core First page has a saved state per grid size, "changing the position of a button(s) in one grid size will NOT transition to another grid size, and you would have to move the buttons again in the new grid size. This will be the case for all of the pre-made content in Core First." I.e., the *factory* layout keeps core words in stable relative positions as the grid grows, but *user customizations to positions must be redone at every grid size*. **VERIFIED** — https://www.tobiidynavox.com/blogs/support-articles/understanding-pages-and-button-grids-in-td-snap
- **Custom topics survive a grid change but their access point moves.** Vendor support: custom topic content is preserved across grid sizes, but in emergent grids (1x1–2x3) custom topics are reached from the "Supported Navigation page," while at 4x4+ they are reached from the "Topics Menu page," and "customization to the linking buttons, label and symbol, don't transition from the Supported Navigation page to the Topic Menu page" — the family must redo the linking buttons. **VERIFIED** — https://us.tobiidynavox.com/blogs/support-articles/where-did-my-custom-topics-go-when-i-change-the-page-set-grid-size-core-first-page-set
- **Tobii Dynavox itself concedes the motor-planning point** by shipping a separate "TD Snap Motor Plan" page set (Motor Plan 30), described as "based on many of the motor planning principles used by LAMP" — a tacit admission that grid-size progression and motor-plan stability are in tension in Core First. **VERIFIED** — https://us.tobiidynavox.com/pages/td-snap-motor-plan ; https://cenmac.com/2022/09/tobii-dynavox-introduces-motor-plan-30-the-td-snap-motor-plan-page-set/
- Page set comparison across TD Snap page sets (Core First vs Motor Plan vs others): vendor PDF. **VERIFIED (document exists; details not re-quoted here)** — https://download.mytobiidynavox.com/Snap/documents/TDSnap_PageSetComparison_en-INT.pdf

### 2. Proloquo2Go (AssistiveWare) — grid levels + VocaPriority

- **Three vocabulary levels x 23 grid sizes.** The Crescendo vocabulary ships "three different research-based preprogrammed vocabulary levels… Basic Communication, Intermediate Core and Advanced Core," optimized for "23 different grid sizes, ranging from 9 to 144 buttons." **VERIFIED** — https://www.assistiveware.com/vocabularies ; https://www.assistiveware.com/support/proloquo2go/vocabulary-grammar/vocabulary-levels ; https://www.assistiveware.com/support/proloquo2go/appearance/grid-size
- **Grid-size change preserves customizations by design.** AssistiveWare blog: "Changes that you have made to the fringe folders in the original grid size are automatically carried over to the new grid size" without reprogramming, and "the grid size can be increased without the need to re-program" while "the number of core words available to the user increases." **VERIFIED** — https://www.assistiveware.com/blog/adjustable-grids
- **Core word positions:** Crescendo is described as designed "to keep relevant core words in the same location throughout the vocabulary, even on fringe pages" — but whether a specific word occupies the *identical screen coordinate* across all 23 grid sizes is not explicitly documented; smaller grids necessarily show fewer words, so relative (not absolute) position is preserved. **Partially VERIFIED / detail UNVERIFIED** — https://www.assistiveware.com/vocabularies ; https://www.assistiveware.com/blog/adjustable-grids
- **VocaPriority = 3-tier progressive disclosure per folder.** Every fringe folder has Primary ("buttons needed very often, or which are very urgent when needed (e.g. allergies)"), Secondary (behind a "More" button, "words needed less often"), and Storage ("vocabulary related to the folder's topic that you are not yet ready to introduce," visible only in Edit Mode). Growing vocabulary = promoting pre-made buttons from Storage → Secondary → Primary rather than creating buttons. Steps: Edit Mode → tap buttons → toolbar "Move to Primary/Secondary/Storage." **VERIFIED** — https://www.assistiveware.com/support/proloquo2go/organize/buttons-in-folders/prioritize
- **Known layout friction:** AssistiveWare documents that "gaps" appear in grids when paging/Home/Previous buttons interact with grid sizes — a symptom of layout complexity when grids change. **VERIFIED** — https://www.assistiveware.com/support/proloquo2go/troubleshooting/gaps

### 3. Proloquo (AssistiveWare's newer app) — the anti-levels bet

- **Explicit rejection of leveling.** AssistiveWare's design blog says Proloquo uses "a single level with a fixed grid size coupled with an efficient motor plan": "the most frequently used words always available with one tap through two static top rows," "There is no back button," and "the preprogrammed words cannot be moved or removed, so the motor plan remains consistent throughout the user's life." Suitable "for a two-year-old as well as an adult." **VERIFIED** — https://www.assistiveware.com/blog/proloquo-4-grows-with-users ; https://www.assistiveware.com/blog/introducing-proloquo-proloquo-coach
- **Growth = vocabulary expansion, not layout change.** Vocabulary scales "from 4,500 symbol-supported words for young learners to 16,000+ words for adults… while maintaining the identical interface structure" (Crescendo Evolution, built on anonymized data from 10,000+ AAC users). **VERIFIED** — https://www.assistiveware.com/blog/proloquo-4-grows-with-users ; https://www.assistiveware.com/products/proloquo
- **Trade-off (analyst note):** locking preprogrammed words so they "cannot be moved or removed" protects motor plans but removes a whole axis of family customization; this is a deliberate philosophical opposite to Proloquo2Go's 3-levels-x-23-grids matrix from the same company. **UNVERIFIED (interpretation)**
- Companion app Proloquo Coach exists specifically to guide parents in expanding the child's communication — vendor acknowledgment that growth requires coached adults, not just app features. **VERIFIED** — https://www.assistiveware.com/products/proloquo

### 4. LAMP Words for Life (PRC-Saltillo) — "positions never move"

- **Three modes: 1-Hit, Transition, Full.** 1-Hit: 82 core words one touch away. Transition: 205 words at 2–3 hits, building on 1-Hit locations. Full: 4,000+ words with grammar forms. Vendor claim: "The motor plans for words are consistent across vocabulary files so that language can develop without relearning," and "motor plans can grow but not change" (a word's sequence can gain steps ahead of it, but the learned path stays valid). **VERIFIED** — https://lampwflapp.com/features/vocab-levels ; https://documentation.prc-saltillo.com/docs/lamp-wfl-vocab-qrg ; https://lampwflapp.com/pdf/17909v1.2-LAMP%20WFL%20Vocab%20Quick%20Reference.pdf
- **Personal vocabulary has reserved slots** — vendor guidance: "storing personalized words in the first 4-5 spaces on the second row in the transition and full levels allows for the motor plan for these words to remain constant across levels." Customization is constrained *into* the motor-plan philosophy. **VERIFIED** — https://documentation.prc-saltillo.com/docs/lamp-wfl-vocab-qrg (per vendor quick-reference)
- **Philosophy:** full vocabulary from day one via consistent unique motor patterns (Minspeak/Unity + LAMP approach), targeted at autism/developmental disability. **VERIFIED** — https://lampwflapp.com/about ; https://prc-saltillo.com/apps/lamp-wfl
- **SLP/field reports in practice:** third-party reviews note LAMP "has a learning curve and is not always the easiest app for a family to pick up with zero support," with a layout that can feel "overwhelming at first, especially for adults who are new to AAC" — i.e., the abstract Minspeak icons and sequenced hits are hard for *partners* even when they work for users. **UNVERIFIED (review site quote surfaced in search results; source page https://usaspeechtablets.com/blogs/news/lamp-words-for-life-review was egress-blocked and could not be directly retrieved)**
- PRC-Saltillo has since shipped "LAMP Words For Life Discover," an easier on-ramp product — again a vendor conceding the entry-difficulty critique. **VERIFIED (product exists)** — https://prc-saltillo.com/blog/lamp-discover ; https://apps.apple.com/us/app/lamp-words-for-life-discover/id6739362942

### 6. Customization by parents/teachers — steps and friction

- **TD Snap add-a-button-with-photo:** enter Edit mode → select empty cell/create button → edit label/message → "Select the Camera button to add a photo" → exit edit. Vendor training cards, a full editing course, a user's manual and multiple third-party video walkthroughs exist — the existence of an entire training ecosystem ("TD Snap Editing" course 6B303, training card decks, editing guides) is itself evidence of non-trivial operational load. **VERIFIED** — https://learn.tobiidynavox.com/catalog/info/id:697 ; https://download.mytobiidynavox.com/Snap/documents/Training%20Cards/TDSnapBasics_TrainingCards_en-US_1000233_WEB.pdf ; https://download.mytobiidynavox.com/Snap/documents/TD_Snap_UsersManual_en-US.pdf
- **Proloquo2Go:** customization is button-level (create/edit) plus VocaPriority promotion (Edit Mode → select → move between Primary/Secondary/Storage); AssistiveWare positions VocaPriority as making "customization of fringe pages a breeze without needing to delete or create buttons." **VERIFIED** — https://www.assistiveware.com/support/proloquo2go/organize/buttons-in-folders/prioritize ; https://www.assistiveware.com/vocabularies
- **Avaz** markets speed directly at the parent pain point: "Takes only seconds to add words to Avaz, and add many of them all at once"; a Settings Wizard "asks you a few questions about your child and sets up the app"; vocabulary can be printed as a low-tech book. **VERIFIED (vendor claim)** — https://www.avazapp.com/features/
- **Documented parent friction (peer-reviewed):** a systematic review/meta-synthesis of parents' experiences with children's AAC found learning to implement aided AAC "stressful, time-consuming, demanding, and overwhelming"; parents reported abandonment even when "intensely committed to implementation of AAC," attributing it to lacking training. **VERIFIED** — https://doi.org/10.3390/ijerph19138091 (Moorcroft et al.-type meta-synthesis, IJERPH 2022; also https://pmc.ncbi.nlm.nih.gov/articles/PMC9266194/)
- **Abandonment factors include "failure to maintain and alter the system"** — i.e., a system that stops being updated stops being used — alongside poor support, ineffective teaming, and incompatible fit. **VERIFIED** — https://scholars.unh.edu/thesis/385/ ; https://www.researchgate.net/publication/334481212_Speech_pathologist_perspectives_on_the_acceptance_versus_rejection_or_abandonment_of_AAC_systems_for_children_with_complex_communication_needs ; https://www.tandfonline.com/doi/full/10.1080/07434618.2023.2199859
- **Community/forum complaints:** targeted searches did not surface directly citable Reddit r/AAC / AssistiveWare forum threads on programming tedium (Reddit content poorly indexed; forum pages not retrievable). The claim "parents complain online that programming is tedious" is **UNVERIFIED as a specific citation**, though it is consistent with the peer-reviewed meta-synthesis above.
- **Research response to the friction — "just-in-time" (JIT) programming:** Light/Caron/Holyfield (Penn State AAC lab) ran four studies on adding vocabulary *during* interactions rather than pre-programming, motivated by the finding that "Children who use AAC apps often do not have the vocabulary that they require within their daily interactions." **VERIFIED** — https://aac.psu.edu/2016/11/16/asha-2016-supporting-the-language-development-of-children-wccn-just-in-time-programming-of-aac-apps-presentation ; see also the state-of-science review of new AAC technology supports discussing reduced programming demands: https://www.ohsu.edu/sites/default/files/2019-05/New%20and%20emerging%20AAC%20technology%20supports%20for%20children%20with%20complex%20communication%20needs%20and%20their%20communication%20partners%20State%20of%20the%20science%20and_0.pdf

## Part 2 — Evidence and expert practice

### 7. "Presume competence"/robust-from-day-one vs "start small and grow"

- **No prerequisites — professional consensus.** ASHA early-intervention guidance: "There are no prerequisites for considering or introducing AAC," including with very young children; the old candidacy model is rejected. **VERIFIED** — https://www.asha.org/practice/early-intervention-provider-support/augmentative-and-alternative-communication-in-early-intervention/ ; https://janefarrall.com/aac-dont-demand-prerequisite-skills/
- **PrAACtical AAC (Zangari):** presume competence → "we model more robust language"; "Vocabulary instruction is for everyone, and there are no pre-requisite skills needed"; robust systems give access to "rich core and fringe vocabulary… a wide array of communication functions." Practical on-ramp is pedagogical, not technical: "The First 12" core words are a *teaching* starting point inside a robust system, not a 12-button device. **VERIFIED** — https://praacticalaac.org/strategy/the-first-12-getting-started-with-core-words/ ; https://praacticalaac.org/strategy/core-words-direct-vocabulary-instruction-the-beginning-communicator/
- **AssistiveWare's articulation:** "There are no prerequisites to robust AAC." **VERIFIED** — https://www.assistiveware.com/learn-aac/roadblock-aac-users-are-required-to-prove-themselves ; https://www.assistiveware.com/learn-aac/presume-competence
- **Kate Ahern / least dangerous assumption:** the LDA principle (Donnellan 1984) — absent evidence, assume the child *can* — underpins the presume-competence stance in AAC/special ed; Ahern's "motivate, model, move out of the way" framing is widely cited. **VERIFIED** — http://teachinglearnerswithmultipleneeds.blogspot.com/2010/06/living-least-dangerous-assumption.html ; https://publications.ici.umn.edu/ties/foundations-of-inclusion-tips/using-the-least-dangerous-assumption-in-educational-decisions ; https://praacticalaac.org/tag/kate-ahern/
- **The professional counter-nuance:** ASHA Leader "The Pitfalls of Presumptions" — two AAC clinicians argue the presumed-competence framework "can lead to problematic communication system selection" (e.g., choosing a system for the presumed future self that the child cannot operate now). Design implication: robust vocabulary ≠ ignore current access needs; the system must serve both simultaneously. **VERIFIED** — https://leader.pubs.asha.org/doi/10.1044/leader.FMP.23122018.10
- **Net reading:** the field has converged on "robust from day one, scaffold the *teaching* not the *vocabulary*" — the debate that remains is about interface/access scaffolding, which is exactly what growth mechanics must solve. **UNVERIFIED (synthesis)**

### 8. Vocabulary sizes AAC users reach and need by age

- **Toddler core:** Banajee et al. 2003 — 23 core words composed ~96% of naturally occurring toddler (24–36 mo) speech samples (I, no, yes, my, want, go, more, help, all done…). **VERIFIED** — https://www.tandfonline.com/doi/abs/10.1080/0743461031000112034 ; word list: https://www.liberator.co.uk/media/wysiwyg/Documents/Wordlist_Banajee_2003.pdf
- **Preschool:** Marvin et al. 1994 — ~330 most frequently occurring preschool words (context- and time-sampled). **VERIFIED** — https://aaclanguagelab.com/resources/most-frequently-occurring-preschool-words ; https://minspeak.com/wp-content/uploads/2019/07/2-Marvin-List.pdf
- **Core covers most tokens, not most meaning:** a few hundred core words ≈ 80% of everyday spoken tokens. **VERIFIED** — https://www.assistiveware.com/learn-aac/learn-about-core-word-teaching-strategies ; https://aacinstitute.org/core-vocabulary-and-the-aac-performance-report/
- **Typical-development benchmarks (the target the AAC system must chase):** ~50 words expressive at ~18–24 mo; ~1,000 words expressive by age 3; school-age children then add roughly 800–900 root words/year (≈2.2–2.4 words/day, ages 1–12). By age 12 a typically developing child commands tens of thousands of words. **VERIFIED** — https://www.asha.org/about/press-room/articles/what-to-expect-your-childs-communication-development/ ; https://drkarenspeech.com/vocabulary-development-school-age-years/ ; https://www.ncbi.nlm.nih.gov/pmc/articles/PMC4965448/
- **Cross-linguistic caveat:** English core lists don't transfer — "English core vocabulary or 'high-frequency words' are not the same in Spanish or many other languages" (Soto & Cooper 2021 built a developmental Spanish AAC vocabulary); Hebrew and Afrikaans core studies similarly derive language-specific lists. **VERIFIED** — https://slhs.sfsu.edu/culturally-responsive-aac ; https://www.tandfonline.com/doi/full/10.1080/07434618.2023.2210671 ; https://www.ncbi.nlm.nih.gov/pmc/articles/PMC7433287/
- **Gap claim (design-relevant):** aided communicators can only say what someone programmed or what the vocabulary shipped with; JIT-programming research documents that children using AAC apps "often do not have the vocabulary that they require within their daily interactions." **VERIFIED** — https://aac.psu.edu/2016/11/16/asha-2016-supporting-the-language-development-of-children-wccn-just-in-time-programming-of-aac-apps-presentation
- Direct longitudinal counts of aided communicators' achieved device vocabulary sizes by age were not found in retrievable sources. **UNVERIFIED (gap in accessible literature)**

### 9. Longitudinal outcomes — what predicts good outcomes years later

- **Lund & Light (2006, 2007), 3-part series:** followed 7 young men who had used AAC ≥15 years (i.e., from childhood into adulthood), with family and professional interviews. Part III (contributing factors): factors that *impeded* positive outcomes included "attitude barriers, cultural differences, technological barriers, and service delivery limitations." **VERIFIED (abstract-level, via PubMed record)** — https://pubmed.ncbi.nlm.nih.gov/17852054/ ; Part I: Lund & Light 2006, AAC 22:284–299 ("What is a 'good' outcome?"). Fine-grained predictor details (e.g., role of receptive language and literacy) could not be pulled from the paywalled full text. **UNVERIFIED beyond abstract**
- **von Tetzchner (Oslo) longitudinal/international program:** "Aided language skills in children" project and the 2018 special issue on aided language processes, development and use; documents that aided language onset is typically late ("often when they are three years or older") and studies vocabulary development and utterance structure in aided communicators across languages over time. **VERIFIED** — https://www.sv.uio.no/psi/english/research/projects/aided_language_children/ ; https://pubmed.ncbi.nlm.nih.gov/29355044/ ; https://www.sciencedirect.com/science/article/abs/pii/S0885201415000362
- **Martine Smith — "Adolescence and AAC" (Communication Disorders Quarterly):** for adolescents using AAC, effective intervention must address "social networks; peer relationships; language needs, particularly vocabulary; and curriculum access, including literacy development" — i.e., what mattered by the end of the growth arc was vocabulary depth, literacy and peer connection, not grid mechanics. **VERIFIED** — https://dx.doi.org/10.1177/1525740114539001
- **Light & McNaughton 2014 (communicative competence redefined):** long-term competence rests on linguistic, operational, social and strategic competencies *plus* psychosocial factors (motivation, attitude, confidence, resilience) and environmental barriers/supports — outcomes are partner- and environment-dependent, not device-dependent. **VERIFIED** — https://pure.psu.edu/en/publications/communicative-competence-for-individuals-who-require-augmentative/ ; https://aac-learning-center.psu.edu/2019/08/26/communicative-competence-a-new-definition-for-a-new-era-of-communication-light-mcnaughton-2014/
- **No retrievable study follows the same children continuously from preschool (~3) to late elementary (~12) on one AAC system** — the literature is retrospective (Lund & Light) or cohort/cross-sectional (von Tetzchner, Smith). This absence is itself a finding: no incumbent can cite longitudinal proof that its growth path works. **UNVERIFIED (absence claim based on searches performed)**

### 10. Family/teacher customization and outcomes; bilingual/cultural customization

- **Parents as vocabulary informants:** Fallon, Light & Paige (2001), "Enhancing vocabulary selection for preschoolers who require AAC," AJSLP 10:81–94 — foundational work on structured vocabulary-selection tools for preschool AAC. **VERIFIED (citation confirmed; full findings paywalled → details UNVERIFIED)** — https://pubs.asha.org/doi/abs/10.1044/2019_AJSLP-18-0041 (successor framework for preliterate children, ASHA AJSLP 2019, cites it) ; https://communication.bridgeschool.org/planning-for-success/considerations-for-vocabulary-selection/
- **Family involvement in personalization → engagement:** ASHA EI guidance and family-support literature: families "have much to offer in terms of vocabulary selection"; when families use personalized vocabulary in daily routines, children begin using AAC to indicate preferences, with "reductions in frustration." **VERIFIED** — https://www.asha.org/practice/early-intervention-provider-support/augmentative-and-alternative-communication-in-early-intervention/ ; https://leader.pubs.asha.org/doi/10.1044/leader.FTR1.12102007.17
- **Partner instruction is the highest-leverage intervention:** Kent-Walsh et al. 2015 meta-analysis (17 SCED studies, 53 participants): communication-partner instruction produced very large positive effects on AAC users' communication (IRD = 0.83; strategy instruction IRD = .98), effective with caregivers, parents, teachers, aides and peers. **VERIFIED** — https://www.researchgate.net/publication/278045316_Effects_of_Communication_Partner_Instruction_on_the_Communication_of_Individuals_using_AAC_A_Meta-Analysis ; https://apps.asha.org/EvidenceMaps/Articles/ArticleSummary/4ccd2d70-c323-4cc2-9f78-a47f4b7f1e6f
- **Bilingual/cultural customization (2020–2026):** Tönsing & Soto 2020 frame multilingual AAC as required for culturally responsive service; Soto & Cooper 2021 published a developmental early Spanish AAC vocabulary; an AJSLP 2022 scoping review covers developing AAC systems in languages other than English; PrAACtical AAC's Cultural-Linguistic AAC series and SFSU's Culturally Responsive AAC/Multilingual AAC Toolkit turn this into practice guidance (heritage-language access supports family connection, identity, "self-empowerment and autonomy"). **VERIFIED** — https://pubs.asha.org/doi/10.1044/2022_AJSLP-21-00396 ; https://slhs.sfsu.edu/culturally-responsive-aac ; https://praacticalaac.org/featured-posts/cultural-linguistic-aac-feature-considerations/ ; https://pmc.ncbi.nlm.nih.gov/articles/PMC13069598/
- **Parents want better customization tech:** recent HCI work (IDC 2026) gathers parent perspectives on future AAC designs; parent/family perspectives on AI-enhanced AAC identify programming limitation as a target. **VERIFIED (sources exist; detail thin)** — https://dl.acm.org/doi/10.1145/3773077.3812178 ; https://wp0.vanderbilt.edu/youngscientistjournal/article/enhancing-aac-systems-through-artificial-intelligence-parent-and-family-perspective-on-limitations-and-solutions

### 11. Ages 8–12: what changes for older elementary users

- **Adolescence/preadolescence shifts the target:** Smith — social networks, peer relationships, vocabulary (especially peer register), and curriculum/literacy access become the intervention priorities. **VERIFIED** — https://dx.doi.org/10.1177/1525740114539001
- **Peer vocabulary / "banter" evidence:** "Guys, like…yeah…this stuff might actually be pretty important. Teenage vocabulary in peer interactions. Implications for teen AAC users" (Journal of Clinical Speech and Language Studies, 2024): access to "locally relevant slang and abbreviations… may be important to teen AAC users to show alignment and belonging"; "swear words, frequent in most groups in the study, may be also desired by some teen AAC users, to delineate their individuality and teen identity." Teens using AAC have smaller social circles and limited access to peer vocabulary. **VERIFIED** — https://www.tandfonline.com/doi/full/10.1080/22000259.2024.2317470
- **Practice sources on AAC in adolescence** (NWACS): identity, independence, and self-determination needs; systems chosen in preschool often look/sound babyish to a 10–12-year-old. **VERIFIED (source exists; "babyish" phrasing is my summary → UNVERIFIED as quote)** — https://nwacs.info/aac/across-the-lifespan/adolescence/aac-in-adolescence/
- **Literacy transition:** Light's lab "Transition to Literacy" (T2L) features — dynamic text + speech output in AAC software to bridge symbols → orthography; letter-sound instruction works for children with autism and limited speech (Benedek-Wood, McNaughton & Light 2016). By 8–12 the system must be growing *toward text*, not just more symbols. **VERIFIED** — https://aac-learning-center.psu.edu/transition-to-literacy-t2l-decoding/ ; https://dx.doi.org/10.1177/0271121415593497
- **Product fit for 8–12:** Grid 3's "Vocabulary for Life" (young adults, includes spelling grid) and keyboard modes in Avaz are the clearest product acknowledgments of this stage; no incumbent markets a specifically 8–12 social/identity vocabulary (slang, humor, texting register). **VERIFIED for the product facts** (https://grids.thinksmartbox.com/en/supported-learning-wt/vocabulary-for-life ; https://www.avazapp.com/features/) ; **UNVERIFIED (absence claim)** for "no incumbent serves 8–12 social register well."

### 12. School–home collaboration: what makes AAC stick across settings

- **Consistency across settings is a known success factor and a known failure point.** Parents report "lack of consistency in services," poor "communication and coordination of services within and across settings," and insufficient home-school collaboration; multi-stakeholder studies find professionals lacking training and families isolated. **VERIFIED** — https://pmc.ncbi.nlm.nih.gov/articles/PMC9266194/ ; https://www.ncbi.nlm.nih.gov/pmc/articles/PMC11197385/ ; https://www.frontiersin.org/journals/education/articles/10.3389/feduc.2024.1487304/full
- **Untrained parents → abandonment:** parent-training thesis work and abandonment literature: "If parents remain untrained and uneducated communication partners, devices may be abandoned." **VERIFIED** — https://etd.ohiolink.edu/acprod/odb_etd/ws/send_file/send?accession=osu1523887662780829&disposition=inline ; https://scholars.unh.edu/thesis/385/
- **What works:** partner strategy instruction (Kent-Walsh, above, IRD .98); sustained rather than one-off teacher training — "school staff should have access to comprehensive AAC education and practice, extending beyond isolated training sessions"; when teachers increased responsive strategies and augmented input, student turns and picture-based communication increased. **VERIFIED** — https://www.researchgate.net/publication/278045316_Effects_of_Communication_Partner_Instruction_on_the_Communication_of_Individuals_using_AAC_A_Meta-Analysis ; https://www.researchgate.net/publication/230853228_Communication_Partner_Instruction_in_AAC_Present_Practices_and_Future_Directions

## Growth design implications — what a board that truly grows 3→12 must do that incumbents don't

The incumbents each solved one axis of growth and broke another. The evidence suggests a 3→12 system must hold all of these simultaneously:

1. **Separate motor plan from display density — permanently.** TD Snap grows the grid but loses user repositioning across grid sizes (per-grid saved states); TouchChat makes families re-customize everything on WordPower size changes; LAMP and Proloquo freeze positions but at the cost of abstract icons (LAMP) or locked, unmovable vocabulary (Proloquo). A growing board should store each word's *identity and motor path* independently of the current rendering, so any customization (photo, label, position promise) survives every grid/density/level change with zero rework. No incumbent fully delivers this; Grid 3's Super Core Learning ("transfer what you have learned… without re-learning locations") and LAMP's "motor plans grow but never change" are the standards to beat, and both restrict customization to achieve it.
2. **Ship robust, grow the scaffolding.** The professional consensus (ASHA, PrAACtical AAC, AssistiveWare) is no prerequisites and robust vocabulary from day one; the "start small" board is teaching practice, not system design. The right mechanic is progressive *disclosure* of an always-present full vocabulary (Proloquo2Go's VocaPriority Storage→Secondary→Primary is the best incumbent pattern) — plus masking/highlighting for teaching the "first 12" core words inside the full layout — never a smaller vocabulary file. Heed the ASHA Leader caution: robust must not mean inoperable now; access scaffolds (fewer *active* targets, same positions) reconcile the two.
3. **Chase a moving target of ~800–900 new words/year.** Banajee's 23 toddler core words → Marvin's 330 preschool words → tens of thousands by 12: growth is mostly *fringe and personal* vocabulary after the core is mastered. That volume cannot be hand-programmed button-by-button; the system needs just-in-time vocabulary capture (Light lab), bulk add (Avaz's "add many at once"), and pre-staged fringe libraries that promote rather than get created.
4. **Make customization a <30-second, any-adult act — and a shared one.** Parents describe implementation as "stressful, time-consuming, demanding, and overwhelming," and "failure to maintain and alter the system" predicts abandonment. Photo-button creation must be a few taps (photo → auto-label → auto-placed by word class into a stable slot), doable by a grandparent, and synchronized across the child's team — because inconsistency across home/school and ineffective teaming are documented failure modes. Build the partner-training moment into the product (Proloquo Coach acknowledges this need), since partner strategy instruction has the largest effect size in the AAC literature (IRD .83–.98).
5. **Reserve permanent slots for personal/heritage vocabulary from day one.** LAMP's reserved personal-word slots are the right instinct; extend it: family-selected words, home-language words (Soto/Tönsing: English core lists don't translate), and culturally specific vocabulary should have first-class, position-stable homes — bilingual layouts that grow in both languages, not an English board with a "Spanish folder."
6. **Plan the 8–12 identity turn.** By late elementary the needs are literacy (symbol→text transition, T2L-style dynamic text), peer register (slang, humor, swearing-by-policy, texting abbreviations — documented as belonging/identity needs), and an interface that stops looking like a preschool toy without moving a single learned word. Growth must include *register packs* and *visual maturation* (themes/skins, text-forward modes) on top of the frozen motor plan — an axis no incumbent explicitly serves for 8–12.
7. **Never require a "graduation" migration.** Every documented growth cliff (TouchChat file switches, TD Snap topic-link redo, moving apps entirely) creates rework and abandonment risk. The unit of growth should be the *word* and the *scaffold level*, never the *file*. If a child never has to relearn a position or a family never has to re-enter a button between ages 3 and 12, the system has done what no incumbent currently documents doing.
8. **Instrument the growth.** No longitudinal study follows the same children 3→12 on one system; a system that logs (privacy-safely) vocabulary exposure, promotion dates, and use could both drive promotion suggestions and generate the missing longitudinal evidence (as AssistiveWare did with 10,000-user data to design Crescendo Evolution).
